# 网表人工审查

本工具在本机浏览器中审查**已导出的 v2 交付包**，展示全板连接、规格、
逻辑引脚与物理焊盘映射，并保存人工结论。它读取同一份已验证快照，
不修改 Circuit 文件、自动位号、Allegro 网表或 ERC/DRC 结果。

## 启动

```sh
design2allegro review <导出目录>
design2allegro review <导出目录> --port 8765 --no-browser
design2allegro review <导出目录> --state-dir /path/to/review-records
```

默认绑定 `127.0.0.1`，自动选择空闲端口并尝试打开浏览器。终端输出访问地址
和记录路径；按 Ctrl+C 停止服务。界面脚本、图形库及许可证均随 wheel 提供，
运行不需要 Node、CDN 或联网。

启动先执行交付包完整性和网表回读验证。v1 包、文件损坏或存在额外文件的包
会被拒绝。服务固定启动时的快照；导出目录重新构建后，应重新启动审查命令。

## 查看元件与连接

- 左侧切换元件、网络和检查结果。可搜索位号、功能路径、型号、网络名、
  逻辑引脚或 `位号.焊盘`，按人工状态及装配状态筛选。
- 中间按类别显示电阻、电容、电感、二极管、LED、晶体、晶体管、磁珠、
  连接器、芯片、稳压器、开关、跳线和测试点图形；未知类别使用通用图形。
  元件上方显示位号、值或型号，DNP 保留虚线边框。
- 每根引脚单独绘制，显示物理编号和逻辑名称，可点击进入引脚审核。
  NC 用叉号和 NC 文字标注，不连接网络。两脚器件左右排列，多脚器件按物理
  编号自然排序后均分左右；这表示审查位置，不表示实际封装焊盘坐标。
- 普通两端网络直接连接两个引脚；多端网络使用小型分支点，每根引脚独立
  接入。同一元件的多个同网引脚不合并。单端或筛选后仅剩一个可见端点的
  网络显示短线和网名；部分可见的网络同时显示端点数量。
- 电源／地在每个引脚旁显示带真实网名的符号，不绘制跨元件的网络连线。
  不同电源、AGND、DGND 等始终保持独立身份。点击符号或普通连线可查看
  完整网络，定位网络会高亮它的所有可见端点。地符号沿引脚到符号锚点的
  方向自动旋转，接入杆与短线共线，三横线朝向元件外侧；网名保持水平。
  拖动、重新布局及模块折叠后同步更新方向，电源箭头保持原有方向。
- 支持平移、滚轮缩放、拖动元件和 Shift + 拖动框选；引脚和符号随元件移动，
  引脚不可单独拖动。选择计数包含隐藏的选中项，辅助图元不产生新审核对象。
- 点击列表或详情端点可在图与详情之间定位，自动展开目标模块并恢复显示。
  右侧提供全部网络端点、引脚映射、规格原值和 SI 值、额定条件、来源及检查证据。
- “按模块折叠”用模块边界端口汇总第一层模块，每个端口标注内部端点数量。
  点击模块展开。“恢复全部”取消折叠、隐藏和筛选，不清除审核或网络显示设置。
- 自动布局只计算元件与普通网络的粗粒度拓扑，再定位引脚与符号；粗粒度图元
  超过 2,000 个时采用网格布局。缩放低于 0.55 时隐藏引脚等细节文字，选中和
  高亮对象仍显示。列表每页 60 项。

连线端部向引脚外侧伸出，图用于连接审查，不保证达到人工原理图的布线质量。
图表达实际 PCB 网络，不跨电阻、二极管、磁珠或闭合焊桥合并网络。
界面不是电路原理图编辑器或仿真器，也不展示封装几何。

### 电源／地识别和显示纠正

优先级为：用户显示设置 → 网络 `electrical.role` → 有限网名规则 → 普通信号。
显式 `power` / `ground` 分别显示电源 / 地符号，其他显式角色按普通信号显示。
规则忽略大小写，对规范名及别名的最后一级完整匹配：

- 地：`GND`、`AGND`、`DGND`、`PGND`、`SGND`。
- 电源：`VCC`、`VDD`、`VDDA`、`VDDD`、`AVDD`、`DVDD`、`VBAT`、`VBUS`、
  `VIN`、`VOUT` 及其数字后缀，以及 `3V3`、`+3V3`、`5V`、`+5V`、`-12V` 等形式。

名称识别冲突时按普通信号显示；不通过名称子串、引脚类型或零电压推断。
网络详情显示识别依据，可选择“自动识别 / 普通信号 / 电源符号 / 地符号”。
选择自动识别即清除此网络的用户覆盖。

显示设置保存在当前浏览器 localStorage，按板 ID 和交付包指纹隔离，
不写入审核记录 JSON 或交付包。它受浏览器源隔离：更换服务端口或浏览器不会
沿用原源的设置；需要跨次启动复用时使用固定 `--port`。存储不可用时本次会话
仍生效，页面提示未持久化。显示纠正不修改电气声明或自动检查结果。

## 标记、批注和版本

元件、网络和引脚分别具有“待审 / 通过 / 有问题”状态及纯文本批注。
修改约 450 ms 后自动保存；批量标记只作用于明确选中的对象。
保存成功后显示修订号；失败时保留本地草稿并提供重试。

多个页面或服务同时编辑同一记录时，较旧修订会被拒绝，防止覆盖。
发生冲突可先导出 `review-unsaved-draft.json` 保存本地内容，再刷新记录重新编辑。
刷新时会要求确认丢弃尚未保存的修改；关闭带草稿的页面会提示未保存。

默认记录目录为 `$XDG_STATE_HOME/design2allegro/reviews/`，未设置时使用
`~/.local/state/design2allegro/reviews/`。其下按板 ID 哈希和交付包指纹隔离。
`--state-dir` 指定替代根目录，不能位于交付包内部。正常保存采用进程锁、
修订号检查和原子替换；工具不会把额外文件放进交付包。

“导出记录”下载 JSON。“导入记录”仅接受同板、同交付包指纹的数据，先列出
变化、状态及批注，再由用户确认替换。导入是整份替换，缺少的记录恢复为待审。
单条批注最多 20,000 字符，记录文件及请求限制约 8 MiB。
相同交付包复制到其他位置可以复用记录；重新生成后指纹变化则独立审查，
不会自动沿用旧结论。人工通过不会改变自动检查结果，也不是规则豁免。

## 测试与开发

```sh
pip install -e '.[dev]'
python -m playwright install chromium
make test
make test-ui
make verify-package
```

内核/API 测试和浏览器测试只使用临时合成电路及其导出包，不读取板级设计。
`test-ui` 覆盖互相定位、筛选、批注保存、批量操作、记录导入导出、保存失败、
修订冲突、分类图形、独立引脚、连线端点、显示覆盖、密集引脚布局以及
10,000 引脚合成大图。截图和大图耗时记录位于 `build/parser/review-ui/`。
wheel 验证在独立环境启动安装后的 `review` 命令并检查资源、API 和持久化。

图形库为 Cytoscape.js 3.34.3（MIT），来源、完整性信息及许可证随静态资源提供。
